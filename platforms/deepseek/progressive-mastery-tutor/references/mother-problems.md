# 母题卡、变式设计与题量分配

本文件在建立母题、设计变式、处理上传母题或分配题量时读取。母题是单元核心关系的代表题；变式是对同一核心关系的受控迁移，不是换数字凑题。

## 1. 编号与稳定性

| 对象 | 编号 | 示例 |
|---|---|---|
| 单元 | `U01` | `U01` |
| 基础题 | `U01-B01` | `U01-B02` |
| 母题 | `U01-M01` | `U01-M02` |
| 变式 | `U01-M01-V01` | `U01-M02-V03` |
| 答案 | `A-` + 题号 | `A-U01-M01-V02` |
| 模拟卷题 | `P1-Q01` | `P2-Q10` |

规则：

- 编号一旦给出就不复用；删除/替换不把旧号给新题。
- 修订保留原编号，标 `修订 R1`，写清改了什么。
- 拆分：旧题标 `[已拆分]`，新题用新编号并互相引用。
- 废弃：标 `[已废弃]` + 原因 + 替代题编号（如有）。
- 跨语言、跨批次保持同一编号；答案编号由题目编号派生，不另起一套。

## 2. 母题卡（7 字段，严格按序）

每道母题先写卡，再写题干与详解。字段顺序固定，未知写“未提供/待确认”。

```text
### U01-M01 母题卡
- 来源：S01 P88 第7题 [课程明确]（页码/题号按实际提供填写；没有写“未标”）
- 所属单元：U01
- 已知：……
- 目标：……
- 适用条件：……（定义域、取值范围、隐含假设、单位、模型限制）
- 核心关系：……（本题真正考查的关系/原理/不变量）
- 关键决策：……（看到什么信号选什么方法；替代方法及不选理由）
- 通用求解骨架：
  1. ……（检查点：……）
  2. ……（检查点：……）
- 核验方式：……（代入/量纲/特殊值/逆运算/图像/解的个数）
```

写法要求：

- **已知**：条件、数据、单位、图中信息；不要把“目标”混进已知。
- **目标**：要求什么、以什么形式作答（数值/表达式/证明/程序/方案）。
- **适用条件**：写清什么情况下这个方法成立；退化情形。
- **核心关系**：一句话说清“这题真正考什么”，不要写章节名。
- **关键决策**：至少给一个决策点和一条替代路径；说明为什么不用替代路径。
- **通用求解骨架**：编号步骤，每步有检查点；能直接迁移到变式。
- **核验方式**：至少一种可操作的检查；不能只写“检查答案”。

## 3. 变式卡

每道变式必须关联具体母题，不能是“独立新题”。

```text
### U01-M01-V02 变式卡
- 对应母题：U01-M01
- 变式类型：表征转换（文字→表格）
- 保留条件：……（关系、限制、目标类型不变的部分）
- 改变条件：……（具体改了什么）
- 训练目的：……（练哪个决策/表征/迁移）
- 解法变化：母题骨架第 2 步改为先读表取参数，再代入；其余步骤不变
- 题干：……
- 答案编号：A-U01-M01-V02
- 评价：见下（知识点/维度/认知/五维/等级/置信度）
```

四个说明字段（保留条件、改变条件、训练目的、解法变化）是硬性要求；解法变化要指明“哪一步变了”，不能写“方法类似”。

## 4. 六类变式

| 类型 | 操作 | 主要训练 | 解法变化示例 |
|---|---|---|---|
| 参数/数值 | 改数据、系数、范围 | 程序熟练、数据敏感 | 只改代入数值；步骤不变，但需检查新数据是否合理 |
| 条件增减/边界 | 加/删条件，推到边界/退化 | 条件意识、适用性 | 需先判断新条件是否满足公式；可能分类讨论 |
| 表征转换 | 文字↔图↔表↔符号↔程序 | 表征理解与互译 | 先读图/表/代码提取关系，再进入母题骨架 |
| 逆向求解 | 已知结果反求条件/参数 | 关系双向理解 | 从结论反推，需检验解的个数与增根 |
| 错误诊断/反例 | 给错解、找错因、构造反例 | 评价与批判 | 先定位错误步骤，再给正确路径或反例 |
| 新情景/综合迁移 | 换情境或组合已学知识 | 远迁移、建模 | 需先建模/选方法，再复用骨架；可能多解 |

默认 3 道变式至少覆盖 2–3 类，不能全部只换数字。用户明确只要同构练习时，可全为参数/数值，但标“同构练习”，并逐题独立求解、检查数据与解。

## 5. 变式质量规则

- 每题独立求解；不写“同上”“类似母题”。
- 检查数据合理性：新数据是否导致无解、多解、非整数、超范围；必要时调整并说明。
- 检查解的个数与适用条件：尤其逆向题、边界题、含分母/根号/绝对值/实际意义的题。
- 变式形成近→中→远梯度：V01 近迁移，V02 中迁移，V03 远迁移/诊断/综合。
- 不无意改变考点；若改变，明确“新增考点”并补讲解。
- 题干自足：不依赖上一题答案；若必须依赖，标“接上题”，并给可独立作答的条件。
- 不把“更长/数字更大”当成更难；难度按五维评价。
- 变式答案与母题答案同样完整，不因“变式”而省略推导。

## 6. 母题与基础题、变式的关系

- **基础题**：练组件技能/基本程序，通常只改示范中的一个条件；为母题做准备。
- **母题**：单元核心关系的代表题，整合先修与基本技能；是变式的锚点。
- **变式**：在同一核心关系上做受控迁移；不是新单元。
- 若单元没有可迁移的核心关系，允许 0 母题，用基础题 + 迁移任务；不要造题凑数。
- 若一个单元有两个核心关系，拆成两个单元，而不是放两道互不相关的母题。

## 7. 题量分配

### 7.1 默认

- 每单元 2 基础 + 1 母题 + 3 变式 = 6 题。
- 先修微任务不计入题组。
- 不设 5–8 题硬上限；用户要多少写多少；太长按单元分批，但不省略答案。

### 7.2 覆盖优先级

1. 单道母题的 `variants` 覆盖。
2. 单元级 `base`、`mothers`、`variants` 覆盖。
3. 全局默认。

显式覆盖与全局总数冲突时，保留显式覆盖，报告实际总数与差异；不要静默改回默认。

### 7.3 全局母题总数（如“母题共 3 道”）

1. 先满足显式单元覆盖。
2. 再优先保留：用户上传的母题 → 基础/先修单元 → 用户点名单元 → 其余按权重。
3. 总量少于单元数：允许部分单元 0 母题并标注；不要重复使用同一母题。
4. 总量多于单元数：按单元权重分配；同一单元多道母题时，确认它们考不同核心关系，否则合并。
5. 最后输出“实际分配表”：单元 | 母题数 | 基础题数 | 变式数 | 合计 | 说明。

### 7.4 上传母题多于目标

- 默认保留全部**适用**题目，说明实际题量。
- 只有以下情况可排除，并逐条说明：不适用当前范围/年级；题干或关键图缺失无法解；与已有题重复；用户明确要求删减。
- 数量过大时按单元/主题分批，不静默丢弃。
- 若用户给了“只要 N 道”的硬上限，按用户上限选择，并列出未纳入的题及原因，保留编号以便后续补回。

## 8. 上传母题的处理流程

1. 转录题干；图片/公式不清时先给转录并请确认，不静默修正。
2. 标来源与读取状态；检查是否有原答案。
3. 核验原答案（保留原话、更正、理由、位置）。
4. 判断是否在用户范围内；超范围标 `[范围外拓展]`，问是否保留。
5. 建母题卡 7 字段；缺字段写“待确认”。
6. 设计变式；默认 3 道，至少 2–3 类。
7. 逐题求解并评价；检查数据、解的个数、条件。
8. 给出实际题量与分配表；更新检索与续作记录。

## 9. 母题卡质量门槛

- [ ] 7 字段齐全且顺序正确；未知字段没有省略。
- [ ] 来源和页码/题号可追溯；没有编造。
- [ ] 核心关系是一句话，不是章节名。
- [ ] 关键决策有替代路径与不选理由。
- [ ] 骨架每步有检查点，能迁移到变式。
- [ ] 核验方式可操作，不是“检查答案”。
- [ ] 变式有对应母题和 4 个说明字段。
- [ ] 变式不全为换数字；独立求解；检查解个数与条件。
- [ ] 题量与覆盖表一致；超额/0 母题有说明。
